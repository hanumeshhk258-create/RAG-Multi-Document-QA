Project RAG Pipeline Walkthrough

Accurate, step-by-step breakdown of how this application processes queries into verified answers.

STAGE 1

📄 Documents

PyPDF Document Loader

Upload your PDFs and keep the source material in one place. Each uploaded document is validated, parsed, and registered for retrieval.

📄 DBMS_Notes.pdf (14 pages)
📄 SQL_CheatSheet.pdf (8 pages)
📄 SGCUBE.pdf (6 pages)
STAGE 2

✂️ Extraction & Chunking

Recursive Text Splitter

Text is extracted from each page and divided into useful pieces with controlled token overlap to preserve sentence context across boundaries.

Chunk 1: "Relational Databases store tables..." Page 1
Chunk 2: "Primary keys uniquely identify records..." Page 2
Chunk 3: "Foreign keys enforce referential integrity..." Page 2
STAGE 3

✦ Embeddings

all-MiniLM-L6-v2 (384-d)

Each chunk is converted into a numerical representation so related meaning can be found through vector distance rather than only identical wording.

Text chunk → [ 0.042, -0.183, 0.291, 0.015, ..., -0.076 ] (384 dims)
STAGE 4

🔎 Hybrid Retrieval

FAISS Dense + BM25 Sparse

Queries are evaluated across two complementary search paths: FAISS captures semantic synonyms and conceptual relevance, while BM25 guarantees exact keyword and acronym precision.

❓ User Question
FAISS (Dense) Semantic Vectors

Matches concepts and paraphrased wording (e.g., "unique row identifier").

BM25 (Sparse) Exact Keywords

Matches exact technical terms, SQL commands, and acronyms (e.g., "PRIMARY KEY").

⚡ Reciprocal Rank Fusion (Combined Candidates)
STAGE 5

🎯 Reranking

Cross-Encoder (bge-reranker-base)

The strongest retrieved candidates are ranked again for relevance. A deep cross-attention transformer scores the query against each candidate, filtering out false positives.

#1 (0.96) "Primary keys uniquely identify records in table..." ✓ Kept
#2 (0.91) "Candidate keys and composite primary key definitions..." ✓ Kept
#8 (0.34) "Database installation directory instructions..." ✕ Filtered
STAGE 6

🧹 Context Compression

Contextual Extractor

Relevant information is kept while unnecessary text is reduced. Distracting boilerplate, repeated headers, and unrelated paragraphs are compressed out.

Raw Candidates (12,000 characters)
→
Focused Context (3,400 characters • 71% reduction)
STAGE 7

✨ Answer Generation

Google Gemini

The retrieved context is used to create a grounded response. The model is constrained to use only facts present in the verified context.

Verified Context

"A primary key uniquely identifies each row in a relational database table..."

↓
Structured Answer

"A primary key is an attribute or set of attributes that uniquely identifies each tuple..."

STAGE 8

✓ Verification

Claim Verification Engine

Claims are checked against the retrieved evidence before the answer is shown. If an unsupported statement is detected, it is removed or flagged.

✓ "A primary key must be unique across all rows." Supported
✓ "A primary key cannot contain NULL values." Supported
✕ "Primary keys were invented by IBM in 1962." Unsupported (Removed)
STAGE 9

📚 Citations

Page-Level Reference Resolver

Answers include document and page references so users can trace the information back to the source in the embedded PDF viewer.

"Primary keys enforce entity integrity in relational schemas."

What happens when the answer isn't in your documents?

Strict hallucination prevention and safe refusal policy.

Example Unsupported Question

"What is the capital of Jupiter?"

↓
NO RELEVANT EVIDENCE FOUND

"I couldn't find sufficient information about this in the selected documents."

Avoiding Inventions & Guesswork

Standard large language models often generate persuasive-sounding fabrications when asked questions outside their immediate training context.

In this system, adaptive thresholding and strict grounding checks detect when the retrieved candidate similarity is insufficient. Rather than speculating, the assistant politely declines with an actionable refusal.

Neural Reranking: BAAI/bge-reranker-base cross-encoder computes cross-attention scoring between query and candidates.
Safety & Grounding: Fact claim extraction, chunk alignment verification, and strict refusal on out-of-domain queries.
